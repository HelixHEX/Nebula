# Support Matrix

Nebula is pre-alpha. This matrix is the source of truth for public docs and marketing copy until stable releases exist.

## Works Now

| Capability | Status | Notes |
| --- | --- | --- |
| Local repository initialization | Works now | `neb init` creates local `.nebula` metadata. |
| Local status, diff, and save | Works now | Scans the working tree and records snapshots/changesets. |
| Local proposals and merge | Works now | Supports local proposal records and fast-forward merge behavior. |
| File-backed bundle push/pull/clone | Works now | Use `file://` or a local bundle path. |
| Policy-aware projection planning | Works now | Projection plans classify paths and fail when required decisions are missing. |

## Experimental

| Capability | Status | Notes |
| --- | --- | --- |
| Registry server | Experimental | Requires explicit auth and durable storage for non-local deployments. |
| Better Auth RS registry auth | Experimental | `/auth` owns session and API-key lifecycle; production mode requires Postgres and `NEBULA_AUTH_SECRET`. |
| CLI registry auth UX | Experimental | `neb auth` can store credentials, create/list/revoke Better Auth API keys, and recover from common registry auth errors. |
| Release automation | Experimental | cargo-dist, GHCR publishing, checksums, SBOMs, cargo-audit, and cargo-deny are wired, but public release tags still require validation. |
| Streaming sync | Experimental | Requires `BLOB_STORE_URL` and configured object storage. |
| Postgres metadata store | Experimental | Migration exists, production validation is still required per release. |
| Git migration/export | Experimental | Some paths are mirror/planning/materialization flows rather than full hosted Git automation. |
| Vector indexing/search | Experimental | Current OSS behavior is path/content-hash indexing, not production semantic embeddings. |
| Build/deploy handoff | Experimental | Provider execution is not generally implemented for self-hosted OSS users. |
| Backup/restore drills | Experimental | Nebula reports and plans external tool usage; it does not implement a full backup engine. |

## Planned

| Capability | Status | Notes |
| --- | --- | --- |
| Binary installers | Planned | cargo-dist metadata and workflow exist; do not claim installer support until the first validated public tag. |
| Production semantic vector backend | Planned | Requires real embedding generation, storage, search, and policy-filtered retrieval. |
| Full network remote UX | Planned | Auth bootstrap exists; broad hosted remote ergonomics and support guarantees are still planned. |
| Hosted provider integrations | Planned | Astracollab-hosted providers are separate from self-hosted Nebula. |

## Unsupported

| Capability | Status | Notes |
| --- | --- | --- |
| Unauthenticated public registry | Unsupported | Use `NEBULA_REGISTRY_DEV_MODE=1` only for local development. |
| Production file snapshot persistence | Unsupported | File persistence is for local/dev only. Use Postgres/object storage for production paths. |
| Client-selected API token hashes | Unsupported | Better Auth RS API keys are generated by Better Auth and stored hashed. Nebula-owned token minting is disabled for external-auth production modes. |
